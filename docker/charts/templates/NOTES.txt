1. Wait for the pod:

     kubectl rollout status statefulset/{{ $fullname }} -n {{ .Release.Namespace }}

{{- if $render }}
{{- if .Values.streaming.publicEndpoint }}

2. Isaac Sim starts on its own and advertises {{ .Values.streaming.publicEndpoint }}, which you
   set explicitly. Point the Isaac Sim WebRTC Streaming Client at:

     {{ .Values.streaming.publicEndpoint }}:{{ .Values.streaming.signallingPort }}

   ⚠️ Make sure that address really reaches this pod. It is advertised to clients verbatim and
   is never verified — a wrong one fails as a black screen, not an error.
{{- else }}

2. Get the address the stream is published on:

     kubectl get svc {{ include "isaaclab.streamServiceName" . }} -n {{ .Release.Namespace }} \
       -o jsonpath='{.status.loadBalancer.ingress[0].ip}'

   The pod discovers this by itself — nothing needs to be configured. To confirm it did:

     kubectl logs {{ $fullname }}-0 -n {{ .Release.Namespace }} -c wait-clb-ip

   Point the Isaac Sim WebRTC Streaming Client at that address, port {{ .Values.streaming.signallingPort }}.
{{- if .Values.streaming.loadBalancer.create }}

   ⚠️ Check that CLB's public bandwidth in the console — the platform echoes the request back
   whether or not it honoured it, so kubectl cannot tell you. The default it falls back to is
   1 Mbps, which cannot carry video: the stream connects and then stalls. This release asked
   for {{ .Values.streaming.loadBalancer.bandwidthMbps }} Mbps.
{{- end }}
{{- end }}

3. Watch Isaac Sim start. It runs in the foreground, so its log is the container log:

     kubectl logs -f {{ $fullname }}-0 -n {{ .Release.Namespace }}

   The UDP media port is bound lazily, at session setup, so it stays absent until the first
   client connects — that is expected, not a fault. To check it once a client is connected,
   without needing any tools in the image:

     kubectl exec {{ $fullname }}-0 -n {{ .Release.Namespace }} -- \
       sh -c 'grep -i ":$(printf %04X {{ .Values.streaming.mediaPort }}) " /proc/net/udp'

   ⚠️ Connect with the Isaac Sim WebRTC Streaming Client — a browser cannot open this directly.
   The signalling port speaks WebSocket rather than HTTP, and this Isaac Sim serves no client
   page of its own: NVIDIA retired the extension that used to host one. Browser access would
   need a front end built on the Omniverse WebRTC Streaming Library.
{{- else }}

2. Exec in and launch training:

     kubectl exec -it {{ $fullname }}-0 -n {{ .Release.Namespace }} -- bash

   Nothing is exposed in train mode, by design. Write checkpoints and logs under
   {{ .Values.persistence.mountPath }} so they survive the pod.

   ⚠️ --stream renders a camera view, so it needs a GPU that can RENDER, not just compute.
      A run using it belongs on an instance type valid for BOTH modes.
