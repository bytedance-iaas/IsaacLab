{{- if .Values.streaming.exposeNvcfPort }}

{{- end }}
  Restrict it at the network layer — a CLB ACL or a security group rule allowing only the source
  addresses that should reach it. The chart cannot do this for you. Or use
  streaming.loadBalancer.addressType=PRIVATE and reach it over a bastion or VPN.

1. Wait for the pod:

     kubectl rollout status statefulset/{{ $fullname }} -n {{ .Release.Namespace }}

{{- if $render }}
{{- if .Values.streaming.publicEndpoint }}

2. Isaac Sim starts on its own and advertises {{ .Values.streaming.publicEndpoint }}, which you
   set explicitly. Point the Isaac Sim WebRTC Streaming Client at:

     {{ .Values.streaming.publicEndpoint }}:{{ .Values.streaming.signallingPort }}

   ⚠️ Make sure that address really reaches this pod. It is advertised to clients verbatim and
   is never verified — a wrong one fails as a black screen, not an error.
{{- else }}

2. Get the address the stream is published on:

     kubectl get svc {{ include "isaaclab.streamServiceName" . }} -n {{ .Release.Namespace }} \
       -o jsonpath='{.status.loadBalancer.ingress[0].ip}'

   The pod discovers this by itself — nothing needs to be configured. To confirm it did:

     kubectl logs {{ $fullname }}-0 -n {{ .Release.Namespace }} -c wait-clb-ip

   Point the Isaac Sim WebRTC Streaming Client at that address, port {{ .Values.streaming.signallingPort }}.
{{- end }}

3. Watch Isaac Sim start. It runs in the foreground, so its log is the container log:

     kubectl logs -f {{ $fullname }}-0 -n {{ .Release.Namespace }}
{{- else }}

2. Exec in and launch training:

     kubectl exec -it {{ $fullname }}-0 -n {{ .Release.Namespace }} -- bash

   Nothing is exposed in train mode, by design. Write checkpoints and logs under
   {{ .Values.persistence.mountPath }} so they survive the pod.
{{- $lkurl := include "isaaclab.stream.url" . }}
{{- if $lkurl }}

3. Training publishes a live view to {{ $lkurl }} (room {{ include "isaaclab.stream.room" . }})
   when a run is given --stream:

     ./isaaclab.sh -p scripts/reinforcement_learning/rsl_rl/train.py \
       --task <task> --num_envs 16 --headless --stream

   ⚠️ THAT SERVER IS NOT MANAGED BY THIS RELEASE. This chart deploys Isaac Lab and nothing else —
   LiveKit is separate infrastructure, one server for the whole cluster. Check it is actually
   there and that the Secret this release reads is the one IT reads:

     kubectl get svc -n {{ .Release.Namespace }} -l app=livekit
     kubectl get secret {{ include "isaaclab.stream.secretName" . }} -n {{ .Release.Namespace }}

   Two copies of one credential are free to drift, and the failure mode is a connection that
   authenticates and then fails.
{{- else }}

3. No LiveKit server is named, so nothing is wired into the pod. That is the ordinary case —
   most runs do not stream. `train.py --stream` would fall back to whatever address is compiled
   into livekit_stream.py, which is unlikely to be one you want.

   To publish a live view, set stream.url + stream.existingSecret. To watch it in a browser, add
   viewer.enabled=true, which requires both of those.
{{- end }}

{{ if .Values.viewer.service.create }}
   A CLB was provisioned for the page{{ with .Values.viewer.service.bandwidthMbps }} at {{ . }} Mbps{{ end }}. It is deleted with this release, so the

   It carries the PAGE ONLY — a few static files and two small JSON endpoints. Video never

{{- else }}
   It was published on EXISTING CLB {{ .Values.viewer.service.existingId }}, port {{ .Values.viewer.service.port }}.

   ⚠️ If that CLB was created by the CCM (i.e. it belongs to another Service), EXTERNAL-IP will
   stay <pending> forever and the events will show `can not reuse clb ... which is created by
   vke`. The page is still reachable — the listener and backend group are built — but Kubernetes
   never reports the address. Use the CLB's own address, which you already know.

   This release adds only the PAGE to that instance — static files and two small JSON endpoints.
   Video never touches it; the browser talks to LiveKit directly.

{{- else }} port {{ .Values.viewer.service.port }}, reachable only by port-forward (service.type is ClusterIP):
